# ATS Customization Guide

ATS usefulness is practical: can the system parse the resume, and can recruiters find the exact role terms they search for?

## Basic Checks

- Text is selectable.
- Standard section names are used.
- Dates, company names, titles, and education are readable.
- The resume contains the target title or a truthful close variant.
- The skills section contains the strongest JD technologies.

## Keyword Extraction

From the JD, extract:

- exact role title
- required technologies
- preferred technologies
- domain terms
- process words, such as `CI/CD`, `data pipeline`, `incident response`, `requirements gathering`
- regulatory or industry terms only when supported

Reuse exact phrases where natural. Do not replace a phrase the JD likely searches for with a prettier synonym.

## Customization Scope

Default order:

1. target title
2. summary
3. skills order
4. strongest 2-5 bullets
5. optional project ordering

Stop once the resume is truthful, readable, and matched. More editing is not always better.

## Red Flags

- Claiming tools only because they appear in the JD.
- Adding unsupported metrics.
- Copying one employer's tailored bullet into another employer's resume.
- Making the resume sound like a senior full-time professional when the candidate is applying as a student/intern.
- Creating a sparse one-page resume by deleting useful evidence.

## Final Checklist

- Hard gates checked.
- 5-15 exact JD phrases reused where truthful.
- 10-30 hard skills prioritized.
- Every changed bullet traces to private evidence.
- Resume is one page when expected.
- Upload-facing filename is short.
- Unsupported JD terms are listed instead of forced.
